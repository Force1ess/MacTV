# 夸克网页播放协议验证

## 已修复的解析错误

旧适配器使用 `/file/v2/play/project`，实际账号返回 HTTP400/code14018。固定桌面客户端User-Agent没有解决。维护者报告中的同类错误指向该投屏转码接口对平台参数的拒绝，而不是本机未登录。

同一账号/同一影片使用网页接口 `/file/v2/play?pr=ucpro&fr=pc`、`supports=fmp4` 返回 HTTP200/code0，并提供可访问的super/high/low档位。插件0.1.4正式使用这一条路径，不在运行时失败后偷偷切换接口，不使用移动端令牌。

## 已验证的原生媒体读取

解析返回的媒体位于 `video-play-c-sz.drive.quark.cn`，地址包含短期签名查询参数。探针不输出完整URL或参数值。限定1024字节的无Cookie请求返回412；附加固定Referer和User-Agent后仍返回412，另一个文件的结果相同。

经用户分别批准单次探针和实际播放后，限定该精确播放主机的原生会话请求返回206、有效MP4。正式实现将Cookie留在原生请求层，插件只提供公开请求头；跨主机重定向被拒绝，缓存读取也检查会话有效期。不会向其他CDN、JavaScript或日志输出Cookie。

先前3次无会话起播失败记录保留。修复后，正式应用的首次授权、默认拒绝、返回取消、撤销、重新授权、真实画面与时钟、暂停、跳转、倍速及停止共13项通过。实测画面1920×1038，影片时长约5873秒；没有据此声称物理声音输出已验证。

用户首次播放时确认精确的会话主机；本机偏好只保存批准范围，不保存Cookie。登录面板可以撤销播放会话授权，退出账号也撤销；撤销时停止当前夸克播放。用户已批准的范围跨正常重启保留，不依赖开发测试启动参数。

## 首帧与播放准备

同一真实影片、已保存会话、一个进程内100次播放，原先提前加载isPlayable的基线全部成功，但3次超过3秒：观测P99为3259ms，最长7542ms。保留该基线，不删除慢样本。

改为由AVPlayerItem准备受限原生会话的单路MP4后，独立一轮100次全部成功，0次超过3秒；P50为1616ms、P95为1792ms、观测P99为1913ms，最长2181ms，观察窗口内未发现重缓冲。这是1次进程内首次播放加99次重复播放，不代表所有内容、独立冷启动或长时间无卡顿。

首帧仍要求播放器readyForDisplay、有解码画面且实际时钟开始前进；之后观察3秒。没有降低画质或改变计时标准。记录实际准备方式和原生会话主机，避免混合不同路径作比较；测试专用的`--benchmark-eager-playable`保留原准备方式作对照。普通认证MP4采用本次测量通过的播放器准备方式，其他媒体路径保持原行为。

## 可重复诊断

```sh
swift build -c release --product MTVQuarkProbe
.build/release/MTVQuarkProbe web-transcode FILE_ID
```

探针只读MacTV自己已保存的夸克会话，直接请求固定的第一方端点，不读取浏览器数据库。可显式选择projection和original模式，分别检查投屏与下载API的响应；没有静默切换。当前original请求返回HTTP400/code23018，未得到原文件地址。

`--approved-quark-media-session` 仅供明确批准后的单次诊断，精确限制一个播放主机，禁止重定向，不持久扩大会话域。没有批准不要使用。所有模式只输出状态、档位、媒体域名与查询参数名，不输出Cookie、令牌、媒体URL或原始错误正文。实际片源测试不会更改文件。

## 共用请求能力

插件清单可声明固定requestUserAgent，最大512字节，禁止控制字符。旧插件不声明时保留原默认值；不能逐请求由脚本注入。非200响应只额外保留经过类型/范围检查的数字平台错误码，其他正文继续留在原生层。两项专项测试覆盖实际请求头、数字/布尔/字符串区分及敏感正文不跨边界；完整Core235项通过，插件33与TypeScript检查通过。
