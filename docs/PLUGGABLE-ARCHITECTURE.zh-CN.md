# MacTV 即插即用体验插件

[English](PLUGGABLE-ARCHITECTURE.md)

**首批示例插件是相册和 Steam UI。图片源是资源连接，不是插件。**
API 2 已实现异步处理器和并行原生调用，v1 保持兼容。独立 SDK 位于 MacTV-Plugins/sdk；当前是请求级生命周期，不是长期后台进程。

## 正确边界

- 独立功能库：功能行为、内容选择、导航动作与测试，不依赖 MacTV 全局对象或主程序源码。
- MacTV 适配器：把功能库绑定到声明的通用接口。
- 宿主：SwiftUI 通用组件、焦点与返回栈、键盘、播放器/看图器、安装管理。
- 资源服务：目录、NAS、云盘账号等获准连接、受限读取、解码、凭据、系统应用启动。

本地目录、SMB 共享、夸克账号不需要各装一个插件，也没有单独的插件入口、工作进程或安装生命周期。
相册使用图片资源；Steam UI 打开已安装 Steam 的大屏模式，不重新实现 Steam。
B站和夸克保留既有应用/适配器身份；音乐在本阶段仍是旧预览模块，不属于首批独立示例包。

插件可以有自己的源码目录；修改它的功能不能要求修改 MacTV 主程序的 Sources。
底层资源/系统服务保留原生实现，但插件工作流程不能继续写回宿主。

## 两个可独立构建的包

`MacTV-Plugins/gallery` 和 `MacTV-Plugins/steam` 各自包含 package.json、依赖锁、核心代码、
MacTV 适配器、测试、打包入口、清单、README 和许可证。
单独复制任一目录到其他仓库，执行 `npm ci`、`npm test` 即可。
不要求 MacTV 源码、Xcode、运行实例或个人账号。

`build/core.mjs` 是可复用功能库，`plugin.js` 是宿主加载的单文件包，`dist/` 是安装目录。
测试注入图片资源或应用启动接口，不是模拟整个 MacTV。

相册适配器只调用通用 `photos` 资源接口，核心代码不识别夸克名称、引用前缀或账号。
原生资源层适配已有本地/云盘连接，返回元数据和不透明引用。
新增网络协议可能需要资源适配实现；添加一个目录或支持的账号不是安装新插件。

Steam 安装清单里的启动动作从独立核心代码生成，和测试使用同一份数据。
宿主执行审阅过的固定动作；脚本不能临时传入任意系统命令。

## 安装与热插拔

预装示例放在 ExamplePlugins 资源目录，首次复制进普通安装仓库，随后走受管版本和外部插件相同的路径。
它们可以在同一个管理页面更新、启用、停用和删除。
安装登记保存已预装过的记录：重启或新应用包不会把删掉的插件装回来，不会重新启用，也不会覆盖用户安装版本。

- 安装/更新：审阅不可变包，装入独立版本目录，立即刷新入口，不重启 MacTV。
- 停用：取消自己的任务，释放自己的看图/播放状态与应用返回观察，不影响其他模块。
- 启用：立即刷新受管目录和入口。
- 删除：取消、移除登记和代码，保留原始媒体及其他账号连接。
- 重启：恢复用户的启停/删除决定，不直接从主程序包运行示例。

当前更新会先停止该插件正在进行的活动再切换；旧播放实例继续运行到安全交接点是后续 v2 能力。
仍不支持任意资源目录树；SDK 可独立打包，但未发布 npm 命名空间。
安装插件不会重新签名 MacTV 或 Chrome 组件，不会在用户机器运行 npm 或编译 Swift。
Cookie 和 MacTV 会话继续留在原生、账号隔离的受限存储中。

## 程序化验证

`npm --prefix tools run test:plugins` 将两个插件分别复制进隔离测试目录，只安装各自声明的构建依赖，
完成类型检查、构建、测试，并核对生成包。测试目录不包含主程序源码。
`npm --prefix tools run build:plugins` 生成本地安装包目录；应用打包只带产物，不携带 node_modules。

安装仓库测试覆盖预装、实际受管路径、启停、更新、删除、重启和防止恢复已删除插件。
实机还必须证明：同一应用进程中热更新后执行的确实是新代码。

`plugins.list` 读取安装状态。显式开发启动参数 `--allow-plugin-management` 才允许
review、approve、enable、remove；review 返回精确清单和不透明审阅令牌，approve 安装同一份待安装副本。
这些命令与 UI 共用仓库、停止活动和目录刷新。普通启动不开启修改接口。

## 异步 SDK 2

独立 SDK 提供类型契约与可选 definePlugin 工具。处理器可以返回 Promise；原生资源和网络接口返回 Promise。每轮最多 64 个请求，同时执行 4 个，按请求 ID 识别乱序响应。退出页面、停用和更新会取消这一轮调用及待处理工作；阻塞读取不占用 Swift 任务线程池，取消后不能把旧结果写入新界面。

真实脚本进程测试覆盖并行调用、乱序响应、错误捕获后继续、非法 ID 和取消。另用被阻塞的原生操作证明调用方可先取消返回。当前不提供长期后台工作进程、任意 SwiftUI 注入、系统命令或 Git 端口。

启动器可在清单声明要观察的精确窗口标题及全屏偏好。启动器也可声明等待可见窗口就绪后再发送固定动作，避免冷启动的引导/更新进程丢失 URI。通用原生观察器读取公开窗口信息，排除文本/密码输入值，并避免抢走其他应用或游戏焦点；Steam 的具体标题规则在插件内。

## Git 插件来源

设置 → 插件 → 插件来源中管理 Git 仓库，默认官方源为 MacTV-Plugins。
支持 HTTPS、SSH（含 SSH 配置别名）和明确选择的本地 file:// 仓库，可切换分支/标签、启停、移除。
移除来源不删除已安装的插件。图片目录、NAS 和云盘连接仍然是相册资源，和插件来源无关。

应用调用现有 Git，沿用用户的 SSH 密钥、agent 和 Git 凭据助手；不复制私钥，
不另做 GitHub 登录，也不存储独立令牌。缺少密钥、首次主机信任、分支或仓库权限时明确报告。
缺少 Git 会提示安装依赖，不自动弹出命令行工具安装器。当前官方源仍私有，不会自行公开；
本地 Git 测试不能被算作私有 GitHub 认证通过。

缓存是浅层裸仓库，不 checkout、不递归拉子模块、不执行钩子/过滤器，也不运行 npm。
目录格式为 schema 2，条目指定相对插件目录。目录和预编译插件文件都来自同一个提交；
只复制大小受限的已知普通文件，拒绝符号链接、子模块、路径逃逸和清单不匹配。
安装继续使用原有不可变审阅流程，安装记录保存来源、分支和提交；来源改变会使待审批失效。

也可以明确选择随应用提供的离线目录，界面会标明它未检查远程更新。
这不是 Git 失败后的自动替代路径，来源目录也不等于允许自动执行其中代码。
